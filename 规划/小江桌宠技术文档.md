## 1. 它是什么

博客右下角一只常驻的 Q 版猫娘「小江」，随页面滚动固定，可点击、拖动、甩抛、自己走动、打盹。

技术上它是 **5 张静态立绘 + CSS 变换 + 394 行原生 JS**，不依赖任何框架、动画库或第三方插件。没有 Live2D、没有骨骼、没有 canvas、没有 webm 帧动画。

### 文件构成

| 文件 | 行数 | 职责 |
| --- | --- | --- |
| `layout/_partial/pet.ejs` | 28 | DOM 结构，由 `layout.ejs` 在 `</body>` 前注入全部页面 |
| `source/js/pet.js` | 394 | 全部交互逻辑，IIFE 封装，无全局污染 |
| `source/css/pet.css` | 89 | 视觉与动画，全部动画走 `@keyframes` |
| `source/img/pet/*.webp` | 5 张 | 400×400 RGBA，合计 157186 字节（约 154KB） |

## 2. 五张立绘与状态机

CSS 只显示其中一张，靠 `.blog-pet` 根节点的状态类切换：

| 素材 | 用途 | 触发类 |
| --- | --- | --- |
| `catgirl.webp` | 站姿（默认） | 无 |
| `catgirl-lift.webp` | 被拎起 | `.is-dragging` |
| `catgirl-drowsy.webp` | 犯困（过渡帧） | `.is-napping` / `.is-waking` |
| `catgirl-sit.webp` | 屈腿坐下（过渡帧） | 同上 |
| `catgirl-sleep.webp` | 睡姿（终态） | `.is-sleeping` |

### 状态类一览

```
is-petted    点击问候     850ms
is-jumping   蹦跳         1s
is-squish    点击压扁     420ms
is-dragging  拖动中       持续
is-flying    甩出飞行     持续（≤4s）
is-walking   走动中       持续（1–3.3s，按距离算）
is-landing   落地回弹     550ms
is-napping   入睡过渡     1.8s
is-waking    醒来过渡     1s（反向）
is-sleeping  睡着         持续
is-quiet     安静模式     持续（偏好）
is-collapsed 已收起       持续（偏好）
```

### 入睡为什么用「反向播放」

入睡和醒来复用**同一组关键帧**，只改 `--pet-nap-direction`：

```css
.blog-pet.is-napping { --pet-nap-duration: 1.8s; --pet-nap-direction: normal; }
.blog-pet.is-waking  { --pet-nap-duration: 1s;   --pet-nap-direction: reverse; }
```

三个姿态图各有自己的 `opacity` 关键帧（`pet-nap-drowsy` / `pet-nap-sit` / `pet-nap-sleep`），在时间轴上依次淡入淡出，形成「站→困→坐→睡」的 4 帧序列。醒来只需 `reverse`，省掉一套重复定义——但代价是**醒来不能单独调时长曲线**，只能整体改 `--pet-nap-duration`。

## 3. 三个必须理解的机制

改这个宠物最容易踩坑的地方。每一条都是踩过之后才写对的。

### 3.1 命中区域：为什么有个透明的 `.pet-hit`

**问题**：立绘是 400×400 的正方形 PNG/WebP，但人物只占中间一部分——实测不透明像素仅 **44%**，四角只有 **1.7%**。如果让图片本身接收点击，那 56% 的透明区域会照样吃掉鼠标事件，下面的链接点不到。

**解法**：图片全部 `pointer-events: none`，另加一个空的 `<span class="pet-hit">` 覆盖整个按钮，用 `clip-path` 把它裁成人物轮廓：

```css
.pet-hit { position: absolute; inset: 0; pointer-events: auto; z-index: 2;
           clip-path: polygon(33.4% 3.1%, 32.5% 9.4%, ...); }
```

轮廓是用 Python 逐行采样立绘 alpha 通道生成的**32 点多边形**，按 16 个水平带取左右边界。三套轮廓分别对应站姿、拎起、睡姿三种体型，随状态切换。

> **为什么不做成「图片自己接收点击 + 图片自己裁剪」？**
> 实测这两种写法挡点击的效果**完全相同**：`clip-path` 加在 `<img>` 上，方形四角同样能穿透到下面的链接，`elementFromPoint` 在角点返回的一律是页面元素而非图片。所以单独一层的理由不是挡点击，而是**焦点环**：
>
> - 焦点环画在裁剪层上 → 金色描边贴着人物轮廓走，看得出形状（已截图确认）
> - 焦点环画在 `<button>` 上 → 按钮本身没被裁剪，描边会是一个 170×170 的圆角方框，套在人物外面（已截图确认）
>
> 另外也确认过：`drop-shadow` 在两种写法下都正常保留，**不存在**「裁剪吃掉阴影」的问题——最初写这条时想当然了，实测推翻了。
>
> 附带好处：图片全部 `pointer-events: none` 后，热区规则、光标、拖动逻辑只需要维护 `.pet-hit` 一个元素，不必在 5 张图之间同步。

> **改立绘时必须同步更新轮廓**：换图后 `alpha` 分布变了，旧多边形会导致点击区域错位。重新生成长方形采样的脚本见工作记录。

### 3.2 触屏：`touch-action` 与方向判断

**问题**：原来 `touch-action: none`，导致在宠物身上竖滑时页面**完全不动**（实测滚动 0px）。宠物在右下角，正是拇指滑动的热点区。

**解法**分两层，缺一不可：

```css
.pet-avatar { touch-action: pan-y; }   /* 竖向手势交还浏览器 */
```

```js
// 触摸时，竖向为主的移动视为"在翻页"，不启动拖动
if (!drag.moved && event.pointerType === 'touch' && Math.abs(dy) > Math.abs(dx)) return;
```

只改 CSS 不够：`pan-y` 只让浏览器处理竖向滚动，但如果 JS 仍在 `pointermove` 里移动宠物，会产生「页面滚动 + 宠物跟着跑」的双重响应。所以**必须同时**在 JS 侧放弃竖向拖动。

副作用：手机上竖向拖动宠物失效，只能横拖。这是有意的取舍——翻页优先。桌面端（`pointerType === 'mouse'`）不受影响，任意方向都能拖。

### 3.3 层级：`z-index` 与吸顶导航

宠物 `z-index: 9`，吸顶导航 `z-index: 10`。原先是 25，高于导航，拖到顶部会压住导航条且无法点击。

但只改 `z-index` 不够——`position()` 还要限制上边界：

```js
const topLimit = () => {
  const bar = header ? header.getBoundingClientRect() : null;
  return Math.max(10, (bar && bar.bottom > 0 ? bar.bottom : 0) + 8);
};
```

导航滚出视口后 `bottom ≤ 0`，此时回落到 10，宠物可以贴到顶部。

## 4. 甩抛物理

拖动时以 0.3 权重平滑跟踪速度，避免单帧抖动被误判成甩：

```js
drag.velocityX = .7 * drag.velocityX + .3 * ((event.clientX - drag.previousX) / elapsed);
```

松手时速度 > 0.35 px/ms 即转飞行。飞行用 `requestAnimationFrame` 逐帧积分，参数如下：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 速度倍率 | ×2.2 | 拖动速度 → 抛出速度 |
| 速度上限 | vx ±1.4 / vy −1.6~0.6 | px/ms，防止冲出屏幕 |
| 重力 | 0.0032 × dt | px/ms² |
| 边缘反弹 | ×0.62 | 左右墙、天花板 |
| 地面反弹 | ×0.55 | 底部 |
| 地面摩擦 | ×0.82 | 每次触地 |
| 强制收敛 | 4000ms | 兜底，防死循环 |

### 落地判定的坑

最初的写法是**在撞击瞬间**比较垂直速度：

```js
if (Math.abs(flight.vy) < 0.06 && ...) { /* 落地 */ }   // ❌ 永远不成立
```

因为接触地面那一刻 `vy` 恰恰是整段飞行里**最大**的，用静止阈值去比，几乎不可能命中。实测 1.6 秒后仍停在 `is-flying`，位置也没存下来。

正确做法是比较**反弹之后**的速度：

```js
const bounce = Math.abs(flight.vy) * .55;
const settled = bounce < .35 && Math.abs(flight.vx) < .12;
if (settled || now - flight.began > 4000) { /* 停稳 */ }
```

这个 bug 只在真实拖动+松手时暴露，静态读代码看不出来。

## 5. 漫游

空闲 25 秒后沿视口底部走一段（60–200px 随机），随机朝向，走完 25–45 秒后再走。菜单「→ 走两步」可手动触发。

速度固定 0.06 px/ms，`duration = 距离 / 0.06`（所以走 60–200px 对应 1–3.3 秒），用 `requestAnimationFrame` 线性插值。`walk-left` 类记录朝向。

中止条件集中在 `stopWalk()`，`nap()` / `collapse()` / `pointerdown` / `fling()` 都会调用——**任何其他动作开始前都必须停掉漫游**，否则两条 rAF 会同时改 `left`，表现为抽搐。

## 6. 时间与唤醒

### 45 秒打盹

每次交互重置 `idleTimer`：

```js
idleTimer = setTimeout(() => { if (menu.hidden && !drag) nap(); }, 45000);
```

唤醒源：`pointerdown` / `keydown` / `visibilitychange` / **`scroll`**。

最后一个是关键。原先只监听前三个，导致「滚轮读文章」不算活动，读到第 45 秒必睡——而「小江陪你读」这个定位恰好失效。现在滚动也算阅读，2 秒节流避免高频触发。

### 安静模式与减少动画

二者的语义不同，不要混用：

| | 安静模式（用户手动开） | 减少动画（系统偏好） |
| --- | --- | --- |
| 触发 | 菜单切换，存 localStorage | `prefers-reduced-motion` |
| 待机动画 | 关闭 | 关闭 |
| 入睡/醒来过渡 | 跳过，直接换图 | 跳过 |
| Q 弹 / 甩抛 / 漫游 | 关闭 | 关闭 |
| 睡姿 | **保留** | **保留** |
| 键盘移动 | 保留 | 保留 |

代码里统一写法：`if (quiet || reducedMotion.matches) return;`

## 7. 无障碍

- 宠物是可聚焦的 `<button>`，`aria-label` 说明可用操作，`aria-describedby` 指向隐藏的 `.pet-help`
- 方向键移动（10px），`Shift + 方向键` 加速（24px）
- `Escape` 关闭气泡与菜单
- 菜单按钮维护 `aria-expanded`，安静按钮维护 `aria-pressed`
- 手机端控件高度 40px、宽度实测 35px（flex 轻微压缩），命中区域大于视觉圆点
- 焦点环挂在 `.pet-hit` 上而非 button 本身：只有挂在裁剪层上，描边才会贴着人物轮廓；挂在 button 上会变成一个圆角方框（详见 3.1）
- 睡着时 `aria-label` 会变成「小江正在打盹…」

## 8. 持久化

单个 key，`localStorage`：

```js
'jiangnan-blog-pet-v1' → { hidden, quiet, x, y }
```

- 读写都包 `try/catch`：隐私模式下 Storage 抛错时宠物照常工作，只是不记忆
- 换存储结构时**保留这个 key**，否则用户的位置和历史偏好会丢
- 位置只在拖动结束、漫游结束、键盘移动、复位时写入，不是每帧写

## 10. 改动的正确姿势

### 换一张立绘

1. 放进 `source/img/pet/`，保持 400×400 RGBA、单条白尾、深灰金边外套
2. 若是替换现有姿态，**重新生成 `clip-path` 轮廓**（见 3.1）
3. 若新增姿态，在 `pet.ejs` 加 `<img>`，在 `pet.css` 加显示规则

### 调手感

| 想改 | 位置 | 当前值 |
| --- | --- | --- |
| 甩出去的力度 | `pet.js` `fling()` | `×2.2` |
| 甩出触发阈值 | `pet.js` `endDrag()` | `speed > 0.35` |
| 漫游频率 | `pet.js` `wander()` | 首次 25s；漫游后 25–45s；被静音等挡住时重试 20s |
| 漫游距离 | 同上 | 60 + random×140 |
| 打盹等待 | `pet.js` `wake()` | `45000` |
| 点击压扁时长 | `pet.css` `pet-squish` | `420ms` |

## 11. 已知边界

诚实记录，避免误判：

- **不是 Live2D**。只有 5 个离散姿态，姿态之间靠 CSS 渐变衔接，没有骨骼变形、没有口型、不会逐帧连续。
- **手机竖拖失效**。`touch-action: pan-y` 的代价，翻页优先。
- **真机未验证**。所有手机结论来自 Chrome 设备模拟（390×844、360×640），不是实体触屏。
- **漫游可能卡在角落**。目标点在 `10 ~ innerWidth - width - 10` 之间，理论上不会出界，但窗口剧烈缩放时可能位置异常——`resize` 会重新 `position()` 修正。
- **不接聊天服务**。台词是 `pet.js` 里的本地数组，按 `main[data-page]` 分页面取。
- **无余额 / 无会话状态**。与 dsh-pet 不同，这里读不到 DSH 的会话数据。

## 12. 与 dsh-pet 的关系

交互设计上参考了 [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)（甩抛物理、漫游、点击 Q 弹），但**只借鉴行为思路**：

| | 小江 | dsh-pet |
| --- | --- | --- |
| 载体 | 博客主题内 | DSH 插件 |
| 素材 | 5 张静态图 | 100+ 段 webm |
| 动画 | CSS 变换 | 视频帧 |
| 状态来源 | 页面 DOM | DSH 会话事件 |
| 依赖 | 无 | Electron / Cordis |

想要余额气泡或会话状态联动，需要装 dsh-pet 插件本身，不是在博客里加代码能实现的。
