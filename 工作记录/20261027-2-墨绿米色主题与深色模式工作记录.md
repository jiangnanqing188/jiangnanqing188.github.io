- 随后明确方向：「我现在想要主打墨绿色+米色的，这个是浅色系，你再帮我做一个深色系的」——浅色为主、深色为辅，两套并存。

## 一、先量测，不靠读代码猜

改造前用无头 Chrome 实测基线，得到三个具体问题而不是「感觉难看」：

| 问题 | 实测证据 |
| --- | --- |
| 配色没有系统 | `custom.css` 3137 行里散落大量硬编码色值，同一语义在不同组件用不同颜色，深浅无法推导 |
| 无深色模式 | `color-scheme` 缺省，照片在两种意图下都是暗的，但压在照片上的文字用的是随主题反转的令牌 |
| 字号失控 | 实际渲染出 8 档以上字号（11/12/13/14/16/18/20/22/28…），没有层级可言 |

实测同时在验证一件事：无头 Chrome 缓存极重，**每次截图必须换新的 `--user-data-dir`**，否则拿到的是上一轮样式的图。深色模式另外需要先在源内写入 `localStorage`（用同源中转页），否则新 profile 永远落回浅色。

## 二、设计方向（先定规则，再写组件）

一句话方向：**墨绿墨水写在米色纸上**。

| 规则 | 取值 |
| --- | --- |
| 中性色阶 | 每模式一套四层：纸 / 面板 / 浮起 / 内凹，另加两条描边 |
| 强调色 | 只有一个墨绿；深色模式改为浅墨绿以保证对比度 |
| 语义暖色 | 只有一个，**仅**用于已验证的结果与分数，不做装饰 |
| 渐变 | 禁止装饰性渐变；保留的两处是功能性的（首屏照片压暗、头像网格纹理） |
| 字号 | 收敛为恰好六档：12 / 14 / 16 / 20 / 28 / 40 |
| 间距 | 回到 4px 栅格 |
| 照片上的文字 | 固定用 `--lab-on-photo*`，**不跟随模式反转** |

最后一条是本轮最容易踩的坑：照片在两种模式下都是暗的，若用会随主题反转的令牌，浅色模式下就是「近黑的字压在近黑的照片上」。

## 三、实现

### 令牌（提交 b53fee4）

从 0 建立 60 余项语义令牌，浅色 / 深色各一套，结构完全对应：

- 浅色：纸 `#f7f2e7`、面板 `#fffcf4`、浮起 `#f1ebdc`、内凹 `#e8e0ce`、描边 `#d6cbb4`、墨绿 `#1f4d3d`、暖色 `#7d5a20`
- 深色：纸 `#101815`、面板 `#16201c`、浮起 `#1d2924`、内凹 `#25322c`、描边 `#33443c`、浅墨绿 `#8fc9ae`、暖色 `#e0bd88`
- 圆角三档 `--r-chip:4px / --r-control:8px / --r-card:16px`
- 照片层固定：`--lab-scrim:14 14 14`（浅）/ `8 8 8`（深），文字 `--lab-on-photo:#f5efe2`

### 深色模式切换

- 内联 pre-paint 脚本读 `localStorage('lab-theme')` 并写 `documentElement.dataset.theme`，避免刷新闪白。
- 切换时同步三件事：`aria-pressed` / `aria-label` / `title`、`theme-color`（从计算样式的 `--lab-paper` 反推）、以及向 giscus 发 `setConfig` 让评论区跟随。
- giscus 的 `data-theme` 改为读当前模式，原先硬编码 `'dark'`。

### 三处真实缺陷

1. `.hero-result` 压在首屏照片上，却用 `--lab-ink` / `--lab-muted` → 浅色模式下近黑字压近黑照片。改指 `--lab-on-photo*`。
2. `.toc` 阴影写了 `color-mix(in srgb, var(--lab-scrim) 40%, transparent)`——而该令牌是裸 RGB 三元组，整条声明被浏览器静默丢弃。改用 `rgb(var(--lab-scrim) / 0.18)`。
3. `.pet-hide` / `.pet-menu-toggle` / `.code-copy` 沿用 UA 默认 `padding: 6px`，造成 6px 非栅格间距；显式写 `padding` 后回到 4px。

## 四、参照真实博客的收细（提交 b53fee4 第二部分）

用 `web_fetch` 直接取了三家阅读型博客的线上 CSS（`web_search` 因缺 API key 不可用），只看被量到的数值：

| 博客 | 事实 | 是否采用 |
| --- | --- | --- |
| Maggie Appleton | 正文 `Canela Text` 衬线，界面 `Lato` 无衬线，基准字号 20px | 采用「衬线正文 + 无衬线骨架」 |
| Julia Evans | 正文 `PT Serif`，chrome 用 `Montserrat` | 同上，交叉印证 |
| Bartosz Ciechanowski | 正文 `max-width:44rem`（704px） | **未采用**：本站实测 880px、34–42 汉字/行，已在 30–40 舒适区，改窄反而更差 |

据此改了四处：

- `--lab-read` 引入 `Noto Serif CJK SC` 正文字体栈，正文 20px/1.9；标题与界面仍走 `--lab-sans`。
- 引用块 14px → 20px（与正文同级）、行高 1.85、底色 `--lab-raised`、左侧 2px 墨绿线。原来把「项目摘要」这种关键内容做成了全篇最小字，方向反了。手机端同步 14px → 16px。
- 全局标题行高 1.5 → 1.3，中文标题在 1.5 下太散，不成为一个整体。
- 字体栈全部收进 `--lab-sans` / `--lab-read`，替换 5 处硬编码（`body`、`.prose table`、`.project-context`、`.mini-project small`、`.aside-note p`），此后改字体只需改一行。

## 五、验证

- 对比度全量重算，两模式 × 三个背景：正文 **13.38 / 14.52**、次要 **6.05 / 8.34**、强调 **8.60 / 9.57**、暖色 5.61 / 10.15，全部高于 AA。
- 实拍核对：浅色/深色 × 桌面/手机 四组，逐张看过；另单独核对含代码块与表格的《YOLOv5 模型训练》两模式。
- `design_audit`：字号仍是**恰好 6 档**；配色仍是「中性色阶 + 1 强调 + 1 暖色」。剩余告警只有两类假阳性——`margin-right:auto` 计算出的 503.4/506.2，以及 CJK 行宽（825px @ 20px ≈ 41 个汉字，工具按拉丁字符数计）。
- 逐元素探针确认字体分工真的生效，而不是写在样式表里没命中：`.prose p` → 衬线、`.prose h2` → 无衬线、`.prose table` → 无衬线；正文列宽 880px。
- `npm run build`、`npm run check:site` 通过；清空 `public/` 与缓存后重跑仍是 **63 页 / 2698 处本地引用**。
