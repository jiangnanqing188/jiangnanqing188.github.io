# 2026-10-27 小江自动停靠与点击穿透

## 起因：用户说「布局」

用户先反馈「你没有改风格啊」，在我列出四个可能后明确否掉全部，补充「我说的布局什么的」，随后从选项里选定：

> 小江的摆位：别压侧栏和目录，让她待在空白里（推荐）

所以这轮范围被限定为**只动小江的摆位**，不碰配色、字号、栏宽与内容顺序。

## 一、先把「布局问题」量成数字

不靠读代码猜，直接用无头 Chrome 量她与页面的实际重叠（`getBoundingClientRect` 求交，沿滚动位取最大值）：

| 页面 | 1440px | 1024px | 被压住的具体内容 |
| --- | --- | --- | --- |
| 首页 | 18952 px² | 27826 px² | 侧栏整卡；1024 下正压头像与「江南」 |
| 文章页 | 18952 px² | 31312 px² | 本篇章节目录，4–6 个链接 |
| 归档页 | 24688 px² | 50185 px² | 侧栏卡与「关于我」按钮 |
| 项目页 | 2147 px² | 273 px² | 轻微 |
| 关于页 | 93 px² | 4476 px² | 1024 下压住标题 |

然后做两件事确认它不是「样式没生效」：

1. 量双栏栅格：1440 → `100 + 918 + 28 + 294 + 100 = 1440`，1024 → `40 + 660 + 24 + 260 + 40`，无溢出、无横向滚动条。**布局本身是好的**。
2. 清空 localStorage 后重测：坐标仍是 `[1248, 676]`，与「固定右下角」完全一致 —— 说明这是 `right: 22px; bottom: 18px` 的写死位置，不是脏数据。

> 顺带排掉一个误判：截图里她出现在**左上角**那次，是我自己测试脚本写进 localStorage 的脏坐标。排除后她确实在右下角，恰好站在头像卡上。

## 二、先证伪「缩一缩就能避开」

直觉是「小一点就不挡了」。先做网格搜索：在 170/140/126/105/96/88/80/72 八个尺寸下，扫描整条底边，看有没有零冲突的位置。

结论是**没有通解**：

- 1440px：170px 在首页、文章页、归档页都找不到完全干净的位置
- 1280/1024px：版心外边距只有 40px，比 88px 的她窄，几何上不可能站进边距
- 390px：正文几乎顶满，缩到 72px 仍有 2 万 px² 重叠

所以「靠缩小解决」这条路被数据否掉了。真正可解的是两件事：**桌面端换位置，所有端保证不挡操作**。

## 三、停靠算法

开页时量一次页面，四个尺寸档 × 四个候选点，按遮挡面积取最小。

```js
// 采集：所有正文与可点元素 → 换算成文档坐标（滚动时不变）
// 权重：链接/按钮/目录/侧栏卡 = 1000；段落/标题/图片 = 1
// 打分：按人物轮廓（l 12%, r 90%, t 3%, b 97%），不按外接方形
//       沿 0/600/1200… 每个滚动位采样累计
// 候选：右下 → 左下 → 右侧栏上沿 → 左侧栏上沿
// 尺寸：170 → 148 → 126 → 105（手机上限 106），任一档零遮挡即停
```

`total = critical × 1000 + cosmetic`，即**宁可缩小自己，也不压一个链接**。

三个关键决定都是被实测逼出来的，不是设计出来的：

1. **跳过容器内部的 a/button**。第一版对 `.home-aside` 和它里面的链接各计一次分，同一块像素被加权两次，结果归档页反而选了更差的位置。
2. **加「侧栏上沿」候选**。归档页侧栏高 1092px、横跨整条底边，左右两角都被占满，只扫两角必然失败 —— 这正是回归测试最后两个红项的成因。加上这条候选后降为 0。
3. **只保留两个角，不做全底边扫描**。中途试过扫描整条底边，结果她漂到 `x=562`、`x=778`（页面正中），比压侧栏更难看。所以边缘锚定优先于全局最优。

`STORAGE_VERSION = 2`：旧坐标存的正是那个压侧栏的位置，抬版本让老访客也拿到新摆位，而不换 key（换 key 会丢掉 `hidden` / `quiet` 偏好）。

## 四、点击穿透：重叠不等于挡路

停靠解决了桌面端，但窄视口依然会重叠。这时靠兜底规则：**指针落在她身上时，先问下面压着什么。**

```js
const underPointer = (x, y) => {
  hitLayer.style.pointerEvents = 'none';        // 先把自己让开
  const el = document.elementFromPoint(x, y);   // 再问这一像素属于谁
  hitLayer.style.pointerEvents = previous;      // 立刻还原
  return el;
};
```

- 下面是 `a / button / input / label / summary` → 转交点击（`below.click()`）
- 否则 → 她自己响应

> 这一行 `pointerEvents = 'none'` 是整套兜底的全部：不加它，`elementFromPoint` 永远返回她自己那一层，问不出答案。

## 五、验证

38 项回归，最终 **38 passed / 0 failed**，含：

| 类别 | 内容 |
| --- | --- |
| 停靠 | 5 页 × 3 宽度 = 15 组，侧栏与目录重叠全部为 0；且都在视口内 |
| 点击穿透 | 归档页被压的「4个项目档案」仍跳到 `/projects/`；文章目录链接滚到 `#7月22日…`（scrollY 0→2506）；手机端压着的项目封面链接可打开 |
| 交互不退化 | 点击打招呼、菜单展开、夸我一句、打盹、收起/叫回、方向键移动 |
| 持久化 | 慢拖 → `auto:false` 存盘 → 刷新还原；方向键微调同样持久 |
| 媒体 | `prefers-reduced-motion` 下正常停靠；`@media print` 下 `display:none` |
| 其他 | 全程零 console 报错；`npm run check:site` 63 页 2698 引用通过；`check-reading` 通过 |

抓到两个真 bug（都不是推理出来的，是回归跑出来的）：

1. **方向键微调不持久**。移动后存 `auto:true`，刷新被自动停靠覆盖。修法是把键盘移动也视为主动摆放。
2. **拖拽后立刻读 storage 得到 null**。初判「保存失效」，实际是速度够快走了 `fling()`，落点要等 4 秒物理结束才写盘。是测试时序错，不是代码错。

## 八、已知边界

- 390px 下她仍会压住文字，这是几何无解；保证的是**不影响操作**（点击穿透），不是「看不见重叠」。
